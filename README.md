# Hot or Cold — iOS take-home case

A small SwiftUI app that lists cities, fetches the current temperature for
each from [open-meteo.com](https://open-meteo.com), and lets you favorite
the ones you like.

Treat it as code you've inherited from a previous teammate.

## What to do

1. Complete the inline `TODO`s in the code.
2. Beyond the TODOs, go through the rest of the code and note anything else
   you'd change. **You don't have to implement everything** — a short list
   of *"I'd also do X, because Y"* is just as good as the diff, often
   better. Producing code is the easy part now; we care more about what
   you'd change and why than about how much you ship.

When you come back, we'll go through it together on a screen-share. Three
things we're especially curious how you think about: the UI, the
concurrency, and the overall architecture. Expect follow-up questions on
anything you wrote, and on anything you flagged as "would change but
didn't".

## Getting started

- Open `Hot or Cold.xcodeproj` and run the `Hot or Cold` scheme.

## How to hand it back

Push to a branch and open a PR against `main`, or send us a zip — either is
fine. Include a hand-off note (PR description or `NOTES.md`) with:

- what you changed,
- what you'd also change with more time, and why.

Aim for **max 2 hours**. Time-box yourself.

#### PS: If you feel inspired to expand on the app, feel free to do so. However, this will not be expected from you, and it will not count negatively if you don't.

## Use AI

We want you to use AI assistance for this — Copilot, Claude, ChatGPT,
Cursor, whatever you reach for normally. Working with AI is how the job
actually looks day-to-day, so this case is more useful to both of us if
you do it the same way. Don't hand-write Swift to "look good"; that isn't
what we're measuring.
